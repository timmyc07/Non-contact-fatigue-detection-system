# P6b-4 首次實錄 belt-truth 離線驗證結果（2026-07-04）

## 背景與目的

P6b-4 離線驗證基礎設施（`rppg/belt_truth_capture.py` + `scripts/rppg_param_replay.py`）
完成時僅以合成訊號單元測試涵蓋，交接文件（`docs/history/2026-07-04-p6b-handoff.md` 第 4 項）
標記「仍待硬體實測」。本次為**首次以真實心跳帶硬體實錄**做的離線候選 ROI 權重驗證，
目的是回答：在真實人臉/真實心跳帶雜訊下，調整 ROI 權重能否讓 rPPG 原始 BPM 更接近真值？

## 資料

- Capture 檔：`recordings/belt_truth_capture/belt_truth_20260704_160448.jsonl`（不入版控）
- 錄製時長約 8 分鐘、14,067 幀 per-ROI RGB 均值 + 心跳帶 BPM
- 心跳帶真值範圍約 80–110 BPM（開頭約 40 秒偏高 101–110，之後回落 82–95）
- 滑動視窗：12s 視窗 / 3s 步進（`rppg_param_replay` 預設），共 157 窗、
  155 窗可同時重算現行與候選 BPM

## 方法

以 `rppg.adaptive_calibration.recompute_raw_bpm_from_roi_windows()`（與線上 A/B 評估
同一顆純運算重算函式）對同一段訊號用多組靜態 ROI 權重重算原始 BPM，對視窗內心跳帶
BPM 中位數算絕對殘差。除 MAE 外加算**中位絕對誤差**（medAE）與**逐視窗勝率**
（該組誤差 < 現行權重誤差的視窗比例），因 MAE 被少數離群視窗主導。
掃描腳本為一次性分析工具（scratchpad），視窗參數與 `scripts/rppg_param_replay.py` 預設一致。

## 結果

現行權重 `{forehead:0.34, L_cheek:0.25, R_cheek:0.25, glabella:0.16}`，n=155：

| 權重方案 | MAE (BPM) | medAE (BPM) | 勝率 vs 現行 |
|---|---|---|---|
| **現行（基準）** | **10.09** | **2.53** | — |
| 等權 0.25×4 | 9.75 | 2.43 | 51.0% |
| forehead 0.6 / 0.15 / 0.15 / 0.1 | 9.86 | 2.51 | 52.3% |
| cheek 偏重 0.15 / 0.35 / 0.35 / 0.15 | 9.80 | 2.69 | 45.2% |
| 前次候選 0.5 / 0.2 / 0.2 / 0.1 | 10.08 | 2.52 | 48.4% |
| glabella 單獨 | 10.88 | **2.33** | 56.8% |
| forehead + glabella（各 0.5） | 11.33 | 2.51 | 55.5% |
| L_cheek 單獨 | 10.98 | 3.40 | 47.7% |
| cheeks 各 0.5 | 10.87 | 2.96 | 43.9% |
| forehead 單獨 | 14.03 | 3.51 | 45.2% |
| R_cheek 單獨 | 15.32 | 4.44 | 36.1% |

### 誤差結構分析

- 離群視窗（絕對誤差 >15 BPM）：34/155（22%），貢獻整體 MAE 10.09 中的 7.96（**79%**）。
- 離群視窗的重算 BPM 集中在兩群：**半頻鎖定**（41–60 BPM，真值 85–95）與
  **諧波鎖定**（~144 BPM）。這些視窗在所有權重組合下都同樣失敗。
- 排除離群後的穩態 MAE 為 **2.73 BPM**，且**幾乎無系統性偏差**（有號偏差中位
  +0.09 BPM、平均 −0.48、σ≈3.98，n=121）——鎖頻正確時原始 BPM 已緊貼真值，
  整體 MAE 10 **不是** `OnlineBpmCalibrator` 的 offset 校準所能修的系統性偏移。

## 結論

1. **本段錄製上，沒有任何候選 ROI 權重超過 0.5 BPM 的採用門檻**
   （`DEFAULT_IMPROVE_MARGIN_BPM`）。最佳為等權（MAE −0.34、勝率 51%），屬誤差邊際內。
2. **誤差預算由「半頻/諧波鎖定」離群視窗主導，ROI 權重對其無槓桿**——四個 ROI 在
   這些時段同時劣化（可能為動作/光照/遮蔽事件），換權重換不掉。
3. 這是對 P6b 護欄設計的正面驗證：`RppgParamAbEvaluator` 的「明確更好且連續 N 次
   才 adopt」在這種資料下會正確地**什麼都不採用**，不會被雜訊誘導亂動權重。
4. 對 rPPG 準確度的實質改善槓桿不在 ROI 權重，而在 **Welch 峰選的半頻/諧波抑制**——
   交接文件已標記此路「風險更高、規劃為僅離線、暫不進 live」，屬重量級數值路徑改動，
   需使用者裁決後才動。

## 限制

- 單一受試者、單一光照場景、單段 8 分鐘錄製；真值偏高（80–110 BPM），未涵蓋
  低心率區間。ROI 權重「在其他場景無用」不能由本次單段錄製外推，只能說本段無效。
- `recompute_raw_bpm_from_roi_windows` 為靜態權重 A/B 比較器，不含 live 的逐幀
  pose 懲罰/品質門檻，結論適用於「候選 vs 現行的相對優劣」，非 live BPM 絕對值。
- glabella 的 medAE 優勢（2.33 vs 2.53）值得後續多場景錄製再看；若重現，可作為
  候選方向啟發式（`propose_roi_weight_candidate`）的證據輸入。
